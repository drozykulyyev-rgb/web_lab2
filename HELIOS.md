## Первая настройка

Нужны два разных свободных порта из разрешённого тебе диапазона.
Первый — HTTP для Apache, второй — FastCGI для Java.
В примере используются настроенные для этого проекта порты 24890 и 24891.

```sh
sh helios.sh setup 24890 24891
sh helios.sh start
sh helios.sh status
```

Скрипт определяет логин, группу и абсолютный путь автоматически.
Настройка сохраняет порты в `config/helios.ports` и проверяет Java 17+,
наличие файлов и синтаксис Apache. Занятый порт обнаруживается при запуске.
Настройку нужно выполнить в конечной папке размещения проекта.

При запуске Java остаётся в фоне после выхода из SSH. Apache запускается отдельно.
Для Java задана начальная куча 16 МБ и максимальная 128 МБ, чтобы JVM не пыталась
автоматически зарезервировать слишком большой объём памяти на Helios.
Если установлен curl, скрипт проверяет `/api/history` через Apache.
Сообщение `Apache -> Java API: OK` подтверждает эту локальную проверку.

## Открытие страницы

При разрешённом прямом доступе используй адрес Helios из LMS и свой HTTP-порт:

```text
http://АДРЕС_HELIOS:HTTP_ПОРТ/
```

Если требуется SSH-туннель, открой второе окно PowerShell на своём компьютере:

```text
ssh -p SSH_ПОРТ -L 8080:127.0.0.1:HTTP_ПОРТ ЛОГИН@АДРЕС_HELIOS
```

Замени все обозначения данными из LMS и своими настройками. Затем открой
`http://127.0.0.1:8080/` и держи SSH-окно открытым.
Туннель даёт доступ с твоего компьютера; сам по себе он не делает сайт публичным.
Доступность для преподавателя проверь по правилам курса.

## Проверка работы

1. При R = 2 точка X = 1, Y = 0.5 должна попасть в область.
2. При R = 2 точка X = 3, Y = 1 должна дать промах.
3. Y = 5, Y = -3, буквы и пустое поле должны отклоняться.
4. Y = 4.999999999999999999 должно приниматься без округления в таблице.
5. При нескольких X должны появиться несколько строк.
6. После обновления страницы история должна сохраниться.

## Управление

```sh
sh helios.sh check
sh helios.sh status
sh helios.sh stop
sh helios.sh start
```

Для изменения портов сначала выполни `stop`, затем `setup` с новыми портами.
Перед заменой JAR также останови приложение. Перезапуск Java очищает историю
в памяти. LocalStorage пока не реализован.

Журналы:

```sh
tail -n 40 logs/java.log
tail -n 40 logs/apache-error.log
tail -n 40 logs/apache-access.log
```

Если запуск сообщает об ошибке проверки API, процессы могут остаться запущенными.
Посмотри журналы и выполни `sh helios.sh stop` перед повторным запуском.

## Пути программ

По умолчанию используются пути из выданного шаблона Helios:

- Apache: `/usr/local/sbin/httpd`.
- Модули: `/usr/local/libexec/apache24`.
- MIME-типы: `/usr/local/etc/apache24/mime.types`.
- Java: команда `java` из PATH.

Если на сервере установлены другие пути, укажи их через переменные `HTTPD`,
`APACHE_MODULE_DIR`, `APACHE_MIME_FILE`, `JAVA_BIN` перед запуском скрипта.
Например, `export JAVA_BIN=/путь/к/jdk-17/bin/java`.
Такие настройки нужно повторить в новой SSH-сессии либо сохранить в настройках
своей оболочки. Системные конфигурации Apache не изменяются; sudo не требуется.

Конфигурацию запускай через `helios.sh`: он передаёт Apache необходимые
переменные окружения с путями, пользователем и портами.

## Пересборка

Для готового архива сборка на Helios не нужна. Если изменён Java-код,
при наличии JDK 17+ выполни:

```sh
sh helios.sh stop
sh build.sh
sh helios.sh start
```

HTML/CSS/JS можно обновлять без пересборки JAR. После этого обнови страницу.

## Что проверено до загрузки

Проверки Java, HTTP API и FastCGI выполнены локально. На Helios проверены
Java 21, синтаксис Apache, запуск обоих серверов, выдача HTML/CSS/JS,
передача запросов через Apache, точность длинных дробей и серверная валидация.
При повторном запуске `setup` и `start` выведут ошибку, если необходимые условия
не выполнены. Доступность сайта снаружи зависит от сети; используй туннель выше.

Документация Apache:
[конфигурационные файлы](https://httpd.apache.org/docs/2.4/configuring.html),
[FastCGI через mod_proxy_fcgi](https://httpd.apache.org/docs/2.4/mod/mod_proxy_fcgi.html).
